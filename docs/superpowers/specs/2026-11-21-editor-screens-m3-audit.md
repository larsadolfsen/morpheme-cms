# Editor screens against Material 3: audit

Date: 2026-11-21. Audit only: no code, style, test or script is changed. Written for the project manager and the owner.

## Decision and scope

- **Owner, 21 Nov 2026:** Material 3 wins everywhere, also in the editor's screens. Only the page and post editor (its bar, overflow menu, text and block menus) may differ. M3 wins over WCAG; a shortfall is named in `theme/accessibility.json`. This audit does not run `check:contrast` and adds nothing for it.
- **Looked at:** every place in the editor's screens (theme page, settings, lists, dialogs, dashboard, sheets, start screen widgets) where `src/*.css` or `src/*.tsx` draws its own size, colour, spacing, shape, type, elevation, motion or class instead of the theme's Material part, or overrides a part's `--mo-comp-*` or `--mo-sys-*` token. The CSS files read are `src/editor.css` and its six imports (`editor-ui.css`, `editor-forms.css`, `editor-rest.css`, `editor-screens.css`, `editor-settings.css`, `editor-density.css`), 7,038 lines; the `.tsx` files read are the screens, sheets, dialogs and `src/ui.tsx`.
- **Not in the main list:** the page and post editor's own workspace. Its bar, overflow menu, and text and block menus are in their own section at the end, **Page and post editor workspace**, for the owner to decide later.
- **The fixes are not in 0.19.5.** They become 0.19.6 "The editor in Material 3"; the batches in *Fix batches* are the proposed split.

## How it was made

- Each row was found by reading the CSS rule and the `.tsx` that uses its class. File and line numbers were checked by script against the files on 21 Nov 2026 (branch base `bd55765`): every row's file exists, its line is inside the file, and for CSS rows the named selector is on the cited line or within three lines of it (two rows were corrected).
- **M3 pages read** with Playwright on 21 Nov 2026 (Overview, Specs, Guidelines and Accessibility of each): buttons, icon-buttons, button-groups, segmented-buttons, split-button, floating-action-button, extended-fab, fab-menu, text-fields, menus, checkbox, radio-button, switch, sliders, chips, lists, cards, carousel, divider, badges, dialogs, bottom-sheets, side-sheets, app-bars, toolbars, navigation-bar, navigation-rail, navigation-drawer, tabs, search, date-pickers, time-pickers, loading-indicator, progress-indicators, snackbar, tooltips (all under `https://m3.material.io/components/<name>/<tab>`), and the foundations `styles/typography/type-scale-tokens`, `styles/shape/corner-radius-scale`, `styles/color/roles`, `styles/elevation/tokens`, `styles/motion/overview/specs`, `foundations/interaction/states/state-layers`, `foundations/layout/understanding-layout/overview` and `…/spacing`, `foundations/layout/applying-layout/compact`, `foundations/content-design/global-writing/word-choice`.
- **What the pages do not print as text:** the Specs tabs keep their token tables in collapsed drop-downs and the type-scale table in folded groups, so the page text gives the token **names** (for example `md.sys.typescale.body-medium`) but not every size or weight. Where a row says "M3 silent", M3 prints no value on the page text and the row names the nearest M3 pattern; a developer reads the image or the expanded table on the Specs tab before fixing it (skill `material-3`, rule 2). Where a number is quoted in a row, the page prints it.
- **Limits:** a few screens were read less closely than the rest (`CommandPalette`, `AddFieldMenu`, `AppFormPage`); the owner's existing recorded deviations (`docs/material-deviations.md`) are still listed as rows where the code draws its own value, with the entry named, because the owner decision of 21 Nov replaces the earlier "editor may differ" ones outside the workspace.

## The patterns that repeat

1. **Type written by hand.** `font-weight` 500 or 600, `0.875rem/1.25rem`, `1rem/1.5rem` and similar sit in own classes where a type role (`md.sys.typescale.*`, theme class `mo-type-*`) belongs. M3 prints the role names; 600 is on no M3 role.
2. **Off-scale shape and spacing.** Radii of 3 px, 0.5 rem, 0.75 rem, 1 rem and 1.375 rem instead of the shape scale (`--mo-sys-shape-corner-*`), and `space-25/75/125/150/250` steps (2, 6, 10, 12, 20 px) that are off the 4/8 dp grid M3 prints.
3. **A part re-drawn on a plain element.** Cards, list rows, chips, bars, fields and choice tiles drawn from own classes on `div`, `a` or `button`, where the theme has `SiteCard`, `SiteListItem`, `SiteChip`, `SiteTopAppBar`, `SiteTextField`, `SiteDivider` and so on (the developer skill's *no own components* rule).
4. **Token overrides in the editor's CSS.** `--mo-comp-card-padding`, `--mo-comp-elevated-card-container-elevation`, `--mo-comp-row-gap`, `--mo-comp-stack-gap`, `--mo-comp-grid-columns`, `--mo-comp-chip-set-bleed`, `--mo-comp-icon-button-small-container-height`, `--mo-comp-menu-container-elevation`, `--mo-comp-toolbar-docked-container-color`, `--mo-sys-target-gap`, `--mo-sys-column-width`, the drawer header's list-item tokens and the density tokens. The rows that set them name the file and line; the theme part should offer the value, or the editor should use the part's own step.
5. **Own colour, mix and opacity.** `#fff`, grey `rgb`, `color-mix` of a role (M3 allows it only for state layers and shadows), `opacity` 50 % and 60 % for a disabled state, and a focus ring in `primary` or `#fff`. The PageSpeed and Google preview colours are documented editor-only parts; they are one row each.
6. **Own motion and elevation.** Own keyframes (sheet, pop, drawer, screen, save bar, pulse) and `cubic-bezier(0.4,0,0.2,1)` with 150 ms or 1200 ms, plus an own level-4 shadow, where M3 has effect motion tokens and elevation levels.
7. **Own full-screen pages and bars.** A 48 rem column with 1/1.5/5.5 rem padding for the crop and block pages, a hand-built screen top bar (`Screen.tsx`), and a save bar and snackbar offset in literal rem.
8. **Phosphor imports.** About 20 files in the dashboard and list scope import Phosphor components directly; whether each is allowlisted in `scripts/phosphor-allowlist.json` was not checked here (`check:phosphor` is the source of truth).

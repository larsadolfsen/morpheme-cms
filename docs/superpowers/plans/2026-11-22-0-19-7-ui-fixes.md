# 0.19.7 UI fixes (plan)

Status: **22 November 2026.** The 0.19 line's fix release (roadmap, 0.19 item 8; `plans/2026-11-18-release-per-feature.md`, *A line that
changes the UI ends with a fix release*). Feature branch `feature/0.19.7-ui-fixes`, cut from `main` once 0.19.6 is on `next`; its first
pull request sets `version` to `0.19.7`. Every batch is a pull request into it.

## What is in it

### A. On the roadmap since 20 and 21 November

1. **Material's colours are M3's colour schemes.** The colour generator, built as `specs/2026-11-21-m3-color-schemes-design.md` says.
   The demo and staging already moved to `#006397` in 0.19.5, so this batch changes the generator only.
2. **The update card counts only the current version** (owner, 20 Nov 2026). `notesSince` in `src/UpdatesNotice.tsx` counts the notes
   of the version in the headline only. *Read more* still leads to all of them.
3. **Scoped app CSS, batch 0** (`specs/2026-11-20-scoped-app-css-design.md`): `data-mo-app="<id>"` on every app block's outer element,
   and `check:app-css -- --report`. There is no contract change.

### B. The page and post editor (owner, 22 November 2026, phone screenshots of a page with a List and a Cards block)

The page and post editor is outside Material 3 and always meets WCAG 2.2 AA (`CLAUDE.md`). The owner's words come first, then what
they mean:

4. **"Sections should only be dotted lines not dotted squares"** and **"Dotted line disappears".** A section is a dotted line across the
   editor where it starts, never a dotted box round its blocks, as decision 4 of `specs/2026-11-11-intuitive-editor-design.md` already
   says. Today the editor draws a dotted box round the section and its blocks. The line always shows (decision 8), also while a block or
   an item is active and while a sheet is open. *Dotted line disappears* (owner's phone screenshot, 13.07): the outer dotted line has
   gaps on the left and right where a block's own dashed box starts inside it, because the block's box covers it. No dotted or dashed
   line in the editor may be broken or covered by another part. The batch finds what covers it (a block's background, margin or outline
   offset) and its `check:screens` unit checks that the line is drawn continuously next to a block. A coloured section still shows its colour box,
   as the site draws it. The active item keeps its own dotted outline (`specs/2026-11-12-inline-block-editing-design.md`).
5. **"Rows should not have a setting"**, **"On cards buttons are added inline"** and **"In block settings, no item should be shown. All
   editing should be inline".** This changes decision 6 of the intuitive-editor spec: an item's icon, image, link and buttons are no longer
   settings. They are edited on the item itself.
   - A list row has no *Row settings*. The row's trailing link button opens the page picker directly. Picking *No page* removes the link.
   - A card has no *Card settings* for its own link or buttons. Buttons are added only with the card's inline *Add button*. The card's link
     is a link button in the card's action row, like the row's. The rule "a card with a page has no buttons" stays: the inline control
     says so when it applies.
   - *Block settings* holds only what applies to the whole block (a list's media kind, a card type, a section colour). It never lists items
     or shows one item's fields. This holds for every block with items: the batch lists them first (List, Cards, Price cards, and any other
     block with an item sheet in `src/standard/*/index.tsx`).
   - Short pickers (page, icon, image, colour) are still opened from the inline control as the picker they are today.
6. **"When a media is selected, show the selected Media and write change media and change [type]".** When an item's media is set, its sheet
   opens on the selected media itself (the icon, the avatar, the image), with two actions under it: *Change media* (pick another kind:
   Icon, Avatar, Square image, Landscape image) and *Change icon* or *Change image*, after the kind. The radio list of kinds shows only
   after *Change media*, or when nothing is set yet. The texts exist (`forms.changeIcon`, `forms.changeImage`); *Change media* is new
   (skill `site-editor-writing`, with its Danish).
7. **"Edit block button in editor tool and block tool are different".** (Settled by B16, which moves *Edit block* out of the toolbar;
   the text below holds until B16 is merged.) The text toolbar's *Edit block* and the block's own action row
   show one action: the same icon, the same label and the same sheet. The batch reads both places, takes the icon the block action row
   uses unless the two do different things, and says in the pull request what each did before.

8. **"Blocks should have no heading and subheading".** The owner, 22 Nov 2026: "block lost heading and subheading when we made inline
   editing, but we forgot to remove it from settings". So this is a leftover, not a new change: the inline blocks no longer show a
   *Heading* or *Subheading*, but their settings still have the fields (`headFields` in `src/standard/*/index.tsx`; the List - Expand
   sheet shows them). The fields go from every block's settings. A heading or text above a block is typed in the page's text.
   Before removing them, the batch checks whether the site still draws a stored heading or subheading. If it does, `morpheme migrate` moves
   the words into the page's text just before the block (the heading at the level the block drew it, the subheading as a paragraph),
   so the page shows the same thing. The migration stays for good (skill `developer`). If the site no longer draws them, the stored
   values are left as they are and the pull request says so. Either way `compare-html` on the demo shows the pages unchanged.
9. **"List from should be a setting. Activate dynamic list and then you get to choose".** *Rows from* (a select with *None*) becomes a
   switch, *Dynamic list* (`On` / `Off`). When it is On, the list to take the rows from is chosen under it; when it is Off, nothing more
   shows and the rows are typed on the block. The same for every block that can take its items from a list (Cards, if it has one; the
   batch lists them). This is a block-level setting, so it stays in *Block settings* (B5). Texts: skill `site-editor-writing`.

10. **"A heading cannot be changed to a label".** A bug (owner, 22 Nov 2026, confirmed: "heading cannot change to label"): in the text toolbar's style menu (the *H2* menu), picking *Label* for a heading
    line leaves it a heading. Each style in that menu must turn any text line into that style, heading to *Label* included, and back again.
    The batch reproduces it on a phone and a computer, fixes it, and adds a `check:screens` unit that takes a heading through every style.

11. **"Clicking on a media opens the media, not the block"**, then **"Tapping a media selects the block and open media"** (owner, 22 Nov
    2026). Tapping or clicking an item's media (a card's image, a row's icon or avatar, an image in the text) does both at once: it
    selects the block, so its action row and dotted outline show, and it opens that media's sheet (B6). Today it only selects the block.
    Enter or Space on the focused media does the same, and closing the sheet returns focus to the media, with the block still selected
    (WCAG 2.2 AA).
12. **"All the image tools should be in the image settings, not the toolbar".** When an image is active, the text toolbar shows no image
    tools. Today it shows *Replace*, *Crop*, *Alt text* and *Delete*. They move into the image's sheet (B6), under the selected image:
    *Change image*, *Crop*, *Alt text* and *Remove*. The toolbar keeps only what it has for any text (undo, redo, *Add block*, the overflow
    menu). This holds for every image in the page and post editor, and B11 is how the sheet opens.

13. **"Faq should have its own block and remove faq setting from list"** (owner, 22 Nov 2026). Today the FAQ is a *List - Expand* with
    the switch *Mark as FAQ* (`faq: true`, `src/standard/expand/index.tsx`). An old FAQ list block becomes one when it is read
    (`faq` in `lib/blocks.mjs`).
    - A standard block **FAQ** of its own (type `faq`): rows of a question (the row's heading) and an answer (the row's text,
      Markdown). It is always in the page's structured data as an FAQPage (`theme/layouts/PageLayout.astro`, as today for `faq: true`).
      It has no switch for that. It is drawn with List - Expand's view and CSS (the design `segmented`, as the FAQ list was drawn), so a
      theme needs nothing new and `check:themes` passes for every theme. It follows B5 (rows edited inline), B8 (no heading or
      subheading) and B9 (*Dynamic list*).
    - **Its settings are List - Expand's** (owner, 22 Nov 2026: "Faq list almost has the same settings as list"). It is built from the same
      parts (`src/standard/rows/listParts`, `rowsFromFields`, `columnsField`, `moreFields`), not a copy. It has *Dynamic list*,
      *Only one open*, *Design* (default `segmented`), the leading media, *Columns*, the text button and *Max rows*. The only differences:
      it has no *Mark as FAQ* (it is always an FAQ), and its rows say *Question* and *Answer* where List - Expand's say heading and text.
      A setting added to List - Expand later goes into the shared parts, so the FAQ gets it too.
    - *List - Expand* loses *Mark as FAQ*. Its texts (`blocks.expand.faq`, `faqToggle`, `faqHint`) move to the FAQ block.
    - **Migration** (kept for good, skill `developer`): a stored *List - Expand* with `faq: true` becomes an FAQ block with the same rows,
      and the old FAQ list (`faq` in `lib/blocks.mjs`, with `question` and `answer`) is read straight into the FAQ block, no longer into
      *List - Expand*. A page's text and structured data stay the same: `compare-html` on the demo shows it, and the tests in
      `lib/blocks-former.test.mjs` change with it. The block picker and the command palette list *FAQ*. A demo page
      `demo/src/content/pages/blocks-faq.md` is added (`scripts/demo-blocks.mjs`).

14. **"Save uses outlined button"** (owner, 22 Nov 2026). In the page and post editor's bottom bar, *Save* is an outlined button (today it
    is tonal). *Publish* stays filled. A bar then holds one filled and one outlined button, the same on a phone and a computer.
15. **"Discard is placed at the bottom in a new section"**, **"Danger: together with delete"** (owner, 22 Nov 2026). *Discard* leaves the
    bottom bar. At the end of the page and post editor's form, after *Content*, a new section **Danger** holds the actions that cannot be
    undone: *Discard* (drop the unsaved changes), *Discard draft* (drop the saved draft and keep what is published), and *Delete page* or
    *Delete post* (the owner confirmed on 22 Nov 2026: "move discard to danger"). Each shows only when it can do something. Each asks before it acts, with the editor's one dialog (`src/ask.tsx`).
    The draft card at the top keeps its message, and its *Discard draft* button moves to Danger. The batch finds where *Delete* is today
    and moves it there, so it is in one place only. The section's heading and the buttons' texts follow `site-editor-writing`
    (Danish too). They use the theme's existing parts (a section heading, outlined buttons in the error colour, if the theme has that
    kind; if it does not, the batch stops and asks the PM, skill `developer`, *no own components*).

16. **The block menu** (owner, 22 Nov 2026: "The block menu use the same styling as the editor menu. Move all block related actions from
    the editor menu into this menu. Add an overflow menu. Bundle items eg add new list item and show me menu for above our below").
    The block menu is the row of actions that shows over a selected block (drag handle, *Move up*, *Move down*, *Hide*, *Edit block*).
    - **Same look as the editor's toolbar:** the same toolbar part, button size, icon size, spacing, surface and outline. It is one part
      used twice, not a copy.
    - **Every block action lives here only.** When the cursor is in a block, the editor's toolbar shows today *Add row above*, *Add row
      below*, *Edit block* and the item's *Link*. These leave the toolbar and go into the block menu. The toolbar keeps what applies to
      any text (the text tools, undo, redo, *Add block*, its overflow menu). This also settles B7: *Edit block* is in one place, so it has
      one icon.
    - **An overflow menu** (⋮) at the end of the block menu holds what is used less (for example *Hide*, *Duplicate*, *Delete block*).
      The batch says which actions go there and why, and the owner reviews it on the demo.
    - **Bundled actions:** related actions share one button that opens a menu. *Add item* (*Add row*, *Add card* after the block) opens
      a menu with *Above* and *Below*. The batch looks for other pairs that bundle the same way (for example *Move* with *Up* and
      *Down*) and lists them in the pull request. It bundles only where that does not add a tap to the commonest action.
    - On a computer and a phone alike. Keyboard: the menu is reached with Tab from the block, its buttons have names, and its menus
      follow the editor's menu pattern (WCAG 2.2 AA).

17. **"Change add block to circle with a plus. Block settings to a cog"** (owner, 22 Nov 2026). *Add block* (in the editor's toolbar and
    wherever else it shows) draws Material Symbols `add_circle`. *Block settings* / *Edit block* (in the block menu, B16) draws `settings`.
    Both are drawn by name through the shared `Icon` (`src/icon.tsx`). The names go into every icon pack's map (`npm run icons`), so
    a site on Phosphor or Lucide gets that pack's circle-plus and cog. No other action may use either icon.

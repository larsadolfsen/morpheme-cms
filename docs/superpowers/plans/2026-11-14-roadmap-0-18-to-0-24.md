- **spec ready**: it can be built.

- **needs a design**: there is no spec yet.

## 0.18 Editor: writing a page

Writing and arranging a page in the editor.

- **Image tools** (owner decisions, 14 November). Released in 0.18.0:
  `specs/2026-11-14-image-tools-design.md`.
  - **No resize.** Images stay full width; there is no "drawn size". An image at another width is another block.
    Replaces the open questions of `specs/2026-11-13-resize-image-design.md`.
  - **A crop view:** full screen, the image in its real proportions, `Format` renamed `Aspect ratio`, the area outside
    the frame darkened with a border, zoom and move.
  - **The image tools in the one bar:** Change image, Crop, Alt text, Remove; for a video, Change address. Handed over
    from 0.17.
  - **One aspect ratio per Cards block**, for all its cards.
- **Command palette and one action registry** (owner decisions, 14 November).
  `specs/2026-11-13-command-palette-and-context-menus-design.md`.
  - It searches actions, the menu's places, and pages and posts by title. Files come later.
  - It opens with `Ctrl+K` and a plain search icon in today's top bar. No FAB.
  - Text actions on a phone too. No owner question open.
  - **One icon per meaning** (section 3.1): `tune` is the settings of the thing you are on (block, section, card, image,
    list); `settings` (the gear) is the editor's Settings and an app's Settings tab only; `edit` (the pencil) edits
    content somewhere else.
- **Block action row fixes:** inside the dotted outline, the Card shape, the theme's buttons. Merged (#640).
- **A choice group replaces segmented buttons** (owner decisions, 14 November): a connected button group when the
  choices fit on one line, otherwise a list of radio buttons, with a live sample where a choice is a look.
  `specs/2026-11-14-choice-group-design.md`. Spec ready.
- **Only Content open** when a page or post opens. Merged (#643).
- **No top image on pages** (owner decisions, 14 November): pages lose the main heading's background image; posts keep
  theirs. No migration. `specs/2026-11-14-no-page-top-image-design.md`. Merged (#658).
- **Paste several lines to make items, and turn one block into another** (owner decisions, 14 November). Released in
  0.18.0: `specs/2026-11-14-paste-and-change-to-design.md`.
  - Pasted lines become items in every repeating block: List, Steps, Segmented list, FAQ, Cards, Table.
  - `Change to…` turns one of those blocks into another and keeps the fields the new block hides.
- **Nightly CMS update:** a site checks npm for a new CMS once a day, at night in the site's time zone. Merged (#637).
- **Saved for the next version** (`todo-next-version.md`): the CMS version app on staging gets English texts (repo
  `morpheme-staging`). Spec ready.

Elevation comes first, in 0.19.5 (owner, 20 November 2026), by hand: `specs/2026-11-20-elevation-design.md`. The steps table then
generates its classes and check without changing them.

The line is for developers only and changes no contract. Component levels, which a customizer would store, moved out of it to
*Ideas without a version*, below (owner, 20 November 2026: "Agreed on moving 0.22.2"), because no customizer is planned yet.

Standardized steps instead of free values, so developers and LLMs (vibe coding) can build on Morpheme without going wrong.
A step sets several values at once.

- **Elevation as the example.** An M3 level sets the tonal surface and the shadow together
  (`--mo-sys-elevation-levelN-color` and `-shadow`), and hover and drag go one level up. Today there is no elevation class;
  parts read the tokens in their own rules.
- **`mo-elevation-N`.** A plain class (like `mo-type-*`, not Tailwind) that sets the background and the shadow together,
  perhaps with the on-surface text colour. Only for plain elements, never for M3 parts: a class wins the cascade and would
  freeze a part's hover and drag level.
- **The same pattern** for colour roles (container and on-container pairs, as section colours already are), the type scale
  (`mo-type-*`, already bundled), shape (the corner scale; Expressive changes shape on press), motion (the springs: fast,
  default and slow, spatial and effects), density, and state layers (fixed by M3, so not customizable, but a
  `mo-state-layer` class would help). One design, "component steps", rather than six features.

The recommendations, in priority order:

1. One machine-readable source table of every step, which generates the CSS tokens, the `mo-*` classes, the docs and the
   checks (and later a customizer's options).
2. Components first; classes only as glue for plain elements, stated loudly so an LLM doesn't rebuild a card from classes.
3. Checks that say what to use instead: fail on raw shadows, radii, durations and pixel spacing with "Use
   `mo-elevation-2`", as `check:editor-colors` and `check:phosphor` already do for their cases.
4. A short developer guide in the npm package, generated from the table (every class, component and token, one example
   each), for the AI of site, theme and app developers.
5. Typed class and token names, so a typo fails the type check.
6. Templates: `morpheme new block | app | theme` gives a skeleton that already passes every check.
7. One command that shows a screenshot of a change.

Items 1 and 3 do most of the work; they build on the class vocabulary that the Tailwind removal (0.19.0, contract 7) rebuilds.

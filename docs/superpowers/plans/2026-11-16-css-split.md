# Plan: move the rest of the CSS into files of their own

Owner request, 16 Nov 2026: "Start migrating the rest of the css into their own files." Step 1 of the developer session: the
inventory and the order of the pull requests. No code is changed by this plan.

The method is proven three times: tokens (`theme/styles/tokens/<origin>/`, #860, `docs/theme-token-files.md`), the type scale
(`theme/styles/type.css`, #861) and cards (`theme/styles/cards.css`, #862). Lists (`lists.css`, #856, with
`docs/theme-css-split.md`) is the pilot. One part or one small family per pull request: a new file in `theme/styles/`
named after the Material 3 component (or the block), imported from `base.css`, in the same `@layer` as the rules came from,
rules unchanged and in their old order.

All line numbers are of `0.18` at `224cc74` (after #861). They go stale at every merge of #856, #862 and #864; the
selector prefixes are the stable key, and each PR recounts its own lines.

## How a pull request proves a pure move

Every PR has the same proof, in its text:

1. **Computed styles.** Every element of every demo page (`/blocks/…` and the rest), at 375, 800 and 1400 px, light and
   dark, before and after: `getComputedStyle` of all properties, compared; 0 differences. The part's own demo page is
   looked at too (`checks`).
2. **Built CSS.** The built stylesheet's declarations before and after, compared as a multiset per `@layer`; the only
   difference is the order *between* files that the PR names.
3. **Collision check (new, from #862's lesson).** A script lists every selector of the moved part that is also matched by
   a rule left outside it in the same layer, at equal specificity. No collision: the import position is free. A collision:
   the new file is imported at the old position (see *Order of the imports*) and the PR says so.
4. `npm run check`, the tests and allowlists that name `ui.css` or `blocks.css` also read the new file (see *Files that
   read the CSS as text*), and an empty changeset (`---` / `---`, no visible change).
5. Under **Components**: *existing, moved only; Material 3 pages not read, a pure move changes no design*.

No custom property is renamed in any PR (the `--mo-*` rename comes after the moves).

## Order of the imports (the cascade)

`ui.css` is one file of 7,800 lines whose rules sit in nine `@layer components` blocks, then keyframes, then two
`@layer fallback` blocks. A new file can be imported from `base.css` only where the rules were, because a CSS `@import`
cannot stand in the middle of a file. So:

- Peel from the **edges** of the remaining `ui.css` where the next part is at its start or end: the import goes before
  or after `ui.css` in `base.css` and the order is kept by construction.
- A part in the **middle** is cut out when the collision check finds none (the usual case: a part's selectors all start
  with its own class). Where it finds one, the PR first splits the rest into a head and a tail file at that part. The
  PR text names it.
- At the end `ui.css` is deleted; `base.css` lists the files in the old order and says why that order matters.

Counts below are rules by their **first selector**. A rule with a list (`:is(a, button).card::before`, the shared
`:where(.button, .icon-button, …)` blocks, the ripple) is attributed to its first selector, so it is listed as *shared*
where it names several parts, and is moved with the part its first selector names unless the PR text says otherwise.

## Lesson from the Checkbox (#892): an element with two part classes

The collision check by selector is not enough. The list's selection box is one element with the classes `checkbox` and `list-item-select-box`;
both rules set `display` and `align-items` at the same specificity, and the list's rule won because it came later in `ui.css`. With
`checkbox.css` imported after `ui.css` the checkbox's rule won, and `checkSelectionBox` failed in CI. So every move also scans the sources
(`className`, `class`, `class:list`, and components that pass a `className` through) for elements that carry a class of the part together with
another class, and checks the order of each such pair. The Checkbox is imported before `ui.css` for this reason (`base.css`, `files.mjs`).

# 0.16: MCP and the store's sections: master plan

Status: not started. Written 2026-11-11. Development starts in 0.16.

Specs: `docs/superpowers/specs/2026-11-11-mcp-design.md` and `docs/superpowers/specs/2026-11-11-store-sections-design.md`. Read both first.

## Goal

An owner connects Claude to the site (read first, drafts later), connectors can call a service's MCP server, and the Appstore shows Themes, Connectors and Plugins (Danish: Temaer, Forbindelser, Udvidelser).

## Owner decisions (2026-11-11)

- Sign-in: OAuth, the Worker is the authorization server, GitHub is the identity, with a consent page.
- Writes: batch 5 is read-only. Writes come in batch 6, after the owner has seen batch 5. The Worker keeps a GitHub token in D1, encrypted with `MCP_VAULT_KEY`, deleted on disconnect.
- Publishing: drafts only. An "Allow publishing" switch per connection, off by default.
- Contract: a new contract 5 (`APP_API` 5) with the fields `role` and `mcp`. Contract 4 stays accepted.
- MobilePay is a plugin.
- Plugin Worker code: batch 2 checks whether Cloudflare dynamic Workers (Worker Loader) can block outbound calls, before any decision.

## Changesets and merging

- Feature PRs carry a `minor` changeset for `@morphemecms/cms`. Never `major`.
- `CLAUDE.md` allows only `patch` or empty until 0.15.1 is released (PR #246). So **no 0.16 feature PR merges before 0.15.1 is released.** Docs-only and spike PRs carry an empty changeset and may merge earlier.
- Every other rule of `CLAUDE.md` applies: a release note (en-US and da-DK) for each owner-visible change, no release step, merges by the PM session.
- Each batch is one PR. A batch that is too large splits at its task boundaries.

## Constraints

- Follow `CLAUDE.md`. Run `npm run check` before every push; `check:screens` for editor changes.
- Worker rule: no pending I/O promise in module memory; `node --test scripts/pending-shared.test.mjs` must pass.
- New secret `MCP_VAULT_KEY` and any D1 migration: ask the owner before anything is written to a live account. Tests use fakes.
- Texts in present tense, en-US first, then da-DK in `src/i18n/da-DK/`. `npm run check:language` passes.
- Confirm the current MCP authorization revision when batch 5 starts and name it in the PR.
- Other repos (`morpheme-appstore`, `morpheme-apps`): follow their own `CLAUDE.md` and open their own PRs; the PM merges.
